# City and region analytics — 2026-10-15

Deployed on October 15, 2026, for Henry's GitHub Pages site, using the account's
verified Workers Free plan. The existing Cloudflare Web Analytics tracker remains
available for its original country and performance reports.

Dashboard: <https://henry-klatt-location-analytics.henry-klatt.workers.dev/>.
The configured D1 database is `henry-klatt-location-analytics`; its ID is in
`wrangler.jsonc`. A daily scheduled task runs at 03:15 UTC.

## What is collected

The browser sends only one of the six approved page paths. The Worker reads the
country, region/state and city supplied by Cloudflare for the incoming request,
then increments a daily total. Unknown locations remain Unknown. City estimates
can be wrong, especially with VPNs and mobile networks.

The D1 database has no IP, visitor ID, cookie, user-agent, coordinates, postal
code, query-string, fragment or precise timestamp columns. Cloudflare still
processes incoming network requests under its own policies. Worker observability
is disabled. A daily task removes counts older than the 180-day window.

Counts are page views, not unique people. Obvious bots are excluded; origin and
path checks reduce accidental use but cannot prevent spoofed or automated counts.
The dashboard shows up to 100 location groups, with complete period totals,
daily totals and page totals. Its location search filters those top 100 groups.

## Private dashboard

Dashboard data requires a random `ADMIN_TOKEN` of at least 32 characters, stored
as a Cloudflare Worker secret. The production key was generated during publishing
and configured as a Worker secret; it is not included in this repository.
The dashboard sends the key in an Authorization header, keeps it in memory only,
and clears it on sign-out/reload. Missing or invalid secrets fail closed.
The HTML shell and JavaScript contain no private data or production key.
Use a long random key, not an account password. Do not put it in a URL, public
source, client tracking script, GitHub variable, or committed configuration.

## Preview and checks

From `website/`:

```sh
npm run analytics:preview
npm test
```

The preview prints its local URL. Sign in with the deliberately public demo key
`local-preview-only-not-a-production-key`. The sample data is fictional and kept
in an in-memory SQLite database; it disappears when the preview stops. It is never
uploaded. Production uses Cloudflare D1. Node.js 22.13+ is required for local SQLite.

## Maintaining this deployment

1. Confirm this Cloudflare account remains on **Workers Free** and D1 Free. Do
   not activate a paid subscription, trial or paid add-on. If the account is
   already paid or a free option is unavailable, stop and report that condition.
2. Reuse the configured Worker and D1 database. Apply only new SQL migrations;
   do not replace the database or reapply old migrations. Local fixtures stay local.
3. Preserve the `ADMIN_TOKEN` Worker secret. If Henry requests a rotation, generate
   a strong random key, update the Worker secret, and hand the new key to Henry
   privately. Never expose an account API token or commit the dashboard key.
4. Deploy this separate Worker with its assets and daily retention task. Preserve
   its actual HTTPS `workers.dev` URL. No custom domain is required. Authenticate
   any CLI through Cloudflare's supported login flow; do not extract browser
   cookies or credentials. If CLI access is unavailable, use Cloudflare's dashboard.
5. Keep `endpoint` in `public/city-analytics.js` set to the actual Worker origin.
   Build/test the website and publish through its existing GitHub Pages workflow.
   Leave `public/analytics.js` in place for Cloudflare's existing performance reports.
6. Check that an actual site visit increases the private dashboard's page counts,
   that local previews stay excluded, and that the API denies unauthenticated reads.
   Local/test geolocation is simulated; a real city estimate needs the deployed Worker.

The Worker needs only its D1 binding, asset binding and `ADMIN_TOKEN` secret.
No production resources are created by the preview or tests. Henry authorized
this publication; subsequent website pushes still require his explicit instruction.

## Cost limits

Workers Free currently allows 100,000 requests/day and 10 ms CPU/request. D1 Free
allows 5 million rows read/day, 100,000 rows written/day, and 5 GB total storage,
with a 500 MB limit per free database. Database operations, dashboard queries and
retention deletions share the quotas; these limits are not a promise of 100,000
tracked page views/day. Quota errors make tracking temporarily unavailable. The
website continues to work if analytics fails. No paid upgrade is configured.
